# Fill the seven requested tables

The existing warehouse was a useful import pipeline, but not a complete automatic
crawler. `stock-crawler sync` still fills the original `dbo.companies`,
`dbo.reports`, and `dbo.fundamentals`. It does **not** fill `dbo.Company` or
`dbo.CompanyFundamental`. These are different tables, even in the same database.

Keep one Python project and one SQL Server. Use `stock-warehouse` for the seven
client tables. No new services, queues or scheduling system are needed.

## What can be filled, and how

| Target table | How data gets there | Remaining requirement |
|---|---|---|
| Market | Repeatable static seed: BIST / TR / Türkiye / TRY | None after database setup |
| MarketIndexMaster | Repeatable seed: XU100, XU030, XU050, XUTUM | These four are a starter set, not every BIST index |
| Company | Selected tickers/names from the bundled KAP registry; database assigns IDs | Verify sector, reporting currency, listing status and IPO date separately; unknown stays NULL |
| CompanyFundamental | Parse saved KAP XLSX files or browser manifests, then load | More source concepts needed for missing metrics; existing files already supply useful partial rows |
| MarketData | `isyatirim-daily` for a no-login EOD snapshot, or reviewed provider CSV | Run the daily job after close; use BIST/vendor data for licensed historical backfill |
| MarketIndexData | `isyatirim-daily` or reviewed provider CSV | Same daily snapshot; historical backfill still needs a sourced file |
| MacroSovereign | New `tcmb-fx` fetch for USD/TRY; existing `evds` for reviewed series; CSV for other sourced observations | EVDS key/profile for other macro series; a CDS data source |

The `reference` command from the older version only generates candidates. Use the
new `seed-reference` command for practical static-table population and
`export-maps` to obtain actual IDs. You do not need to invent IDs or first create
a complete company metadata CSV.

**Schema decision:** optional `init-db` creates missing tables with the diagram's
names and types, but allows NULL for unknown company metadata and financial/macro
observations. This deliberately relaxes completeness for NEW tables. It never
alters existing tables. The original strict financial loading rule remains the
default; `load --allow-partial` is an explicit option. Existing NOT NULL columns
still block incomplete inserts. A missing metric never becomes zero.

## 1. Update your existing project

Extract the updated files into your **existing project directory**. Keep your
`.env`, `local.env`, imports and data. Do not start a differently named Compose
project, because that can create a different SQL volume. The delivered ZIP omits
credentials, caches and generated bytecode.

From that directory:

```bash
bash scripts/crawler-ubuntu.sh build
bash scripts/crawler-ubuntu.sh db
bash scripts/crawler-ubuntu.sh docker init-db
```

For this project's local Docker database, warehouse commands automatically reuse
the same `.env` settings as `docker sync`. `warehouse init-db` selects the
bootstrap login; all ordinary warehouse operations select `crawler_writer`.
There is no need to copy passwords into separate warehouse files.

`--env-file` remains available as an explicit override only when loading a
different external/client database. For that case, start from
`config/warehouse.env.example`, keep credentials out of source control and use a
separate DDL-capable file for `init-db`.

## 2. Create missing tables, seed references and export IDs

```bash
bash scripts/crawler-ubuntu.sh warehouse init-db --apply

bash scripts/crawler-ubuntu.sh warehouse seed-reference \
  --company-file /app/config/companies.txt --apply

bash scripts/crawler-ubuntu.sh warehouse export-maps \
  --output-dir /app/config/warehouse

bash scripts/crawler-ubuntu.sh warehouse inspect
```

Both setup commands can be repeated. Existing IDs and company rows are preserved.
Omit `--apply` for a plan without a database connection. `seed-reference` with no
company-selection option seeds only Market and four indices. For a small pilot,
replace `--company-file ...` with `--tickers ASELS,THYAO`. `--all-registry` is also
available, but registry membership does NOT establish an active listed equity.

If a ticker is missing from the registry, the command fails before writing.
If an existing Company table requires unknown metadata as NOT NULL, the seed
transaction fails without guessing. Populate those facts through your existing
master-data process, or deliberately review the schema with its owner.

The exports are:

- `config/warehouse/client_company_ids.json`: ticker -> actual CompanyId.
- `config/warehouse/client_index_ids.json`: index code -> actual IndexId.
- `config/warehouse/client_market_ids.json`: BIST -> actual MarketId.
- `config/warehouse/company_metadata.csv`: real IDs/names plus known or blank metadata.

Map exports refresh JSON files but preserve an existing metadata CSV so your
manual enrichment is not lost. CompanyId is NOT the KAP ID, registry row number,
or the annual crawler's `dbo.companies.company_id`.

## 3. Load the available KAP financials

A bundled ASELS pilot contains two complementary workbooks for 2025 Q1–Q4.
After seeding ASELS, run:

```bash
bash scripts/crawler-ubuntu.sh warehouse fundamentals \
  --input /app/tests/fixtures/warehouse/asels_2025_baseline.xlsx \
          /app/tests/fixtures/warehouse/asels_2025_operating.xlsx \
  --company-map /app/config/warehouse/client_company_ids.json \
  --calendar-tickers ASELS --currency TRY \
  --output /app/data/warehouse/ASELS-2025.json
```

This parser returns exit 1 because seven financial fields are missing. The JSON
is still written. It contains four period records and eight available financial
metrics; exit 1 means incomplete, not a parser crash. Run the next commands
separately (do not join the parser command to them with `&&`).

```bash
bash scripts/crawler-ubuntu.sh warehouse load \
  --input /app/data/warehouse/ASELS-2025.json --allow-partial

bash scripts/crawler-ubuntu.sh warehouse load \
  --input /app/data/warehouse/ASELS-2025.json --allow-partial \
  --apply
```

With the new nullable schema this loads the observed values and leaves the other
metrics NULL. With your pre-existing strict schema it stages incomplete rows;
check `IssuesJson` for the exact SQL-required fields. Removing `--allow-partial`
restores the strict behavior everywhere.

For real runs use `/app/imports/...` paths for your downloaded XLSX or manifests.
Reuse saved sources; do not download again just to load another table. Quarterly
KAP acquisition is already supported by `kap-script` (see the detailed guide).
The legacy annual `sync` does not automatically invoke this warehouse parser.
Q2/Q3/Q4 flow values are **YTD**, not isolated quarterly flows. Do not subtract
inflation-restated YTD values without a consistent measuring-unit basis.

The seven missing sample metrics are EBITDA, short debt, long debt, cash,
free cash flow, EPS and shares outstanding. Existing `--mapping` handles verified
extra KAP headers; it cannot create facts absent from the source. A newer filing
replaces the old financial snapshot; enrichment of the same filing preserves
already known values. Currency conflicts with known Company.ReportingCurrency
are rejected.

## 4. Fetch one macro field directly: USD/TRY

Read your actual BIST ID from `config/warehouse/client_market_ids.json`. Replace
`YOUR_MARKET_ID` below with that number:

```bash
bash scripts/crawler-ubuntu.sh warehouse tcmb-fx --fetch \
  --market-id YOUR_MARKET_ID \
  --input /app/data/warehouse/tcmb-latest.xml \
  --output /app/data/warehouse/fx.json

bash scripts/crawler-ubuntu.sh warehouse load \
  --input /app/data/warehouse/fx.json \
  --apply
```

No EVDS key is needed for this XML route. It stores the TCMB **indicative foreign
exchange buying rate**, TRY per USD, not a banknote rate or tradable quote. The
XML's actual date is used even if `today.xml` contains the last business day.
Other MacroSovereign fields and the unknown release date stay NULL. For a dated
file use `--date 2025-09-19`; a missing holiday file fails visibly, with no invented
weekend observations. Omit `--fetch` to replay a saved XML.

Other macro observations use the existing `evds` command after configuring a
verified profile and EVDS key, or a sourced normalized CSV. GDP, CPI, tax and debt
must retain their native frequency and agreed units. Keep CDS NULL until a
provider is available. See `docs/WAREHOUSE-IMPLEMENTATION.md` for these contracts.

## 5. Prices and company enrichment

### Online daily close (no login)

The `isyatirim-daily` command uses İş Yatırım's public latest-snapshot endpoint.
It maps provider `quantity` to shares traded and provider `volume` to actual TRY
turnover. It never calculates `ValueTraded` as `ClosePrice * Volume`. The endpoint
accepts batches of up to 20 symbols, so the full company map does not require one
HTTP request per company.

Run a five-symbol pilot after 18:15 Türkiye time:

```bash
bash scripts/crawler-ubuntu.sh warehouse isyatirim-daily \
  --company-map /app/config/warehouse/client_company_ids.json \
  --index-map /app/config/warehouse/client_index_ids.json \
  --tickers THYAO,ASELS \
  --indices XU100 \
  --output /app/data/warehouse/market-daily.json

bash scripts/crawler-ubuntu.sh warehouse load \
  --input /app/data/warehouse/market-daily.json

bash scripts/crawler-ubuntu.sh warehouse load \
  --input /app/data/warehouse/market-daily.json \
  --apply
```

Check the pilot in SQL, then omit `--tickers` and `--indices` for all exported
companies and indices. The command blocks today's intraday snapshot before 18:15 Türkiye
time. `--allow-intraday` exists only for testing; do not use it for the scheduled
EOD load. Missing, suspended or unknown provider symbols are written to `errors`
and are not converted into zero rows. A throttling response stops the run.

The bundled KAP registry has 754 disclosure entities; that is not the same thing
as 754 currently traded equity symbols. A live 50-code sample during implementation
returned 43 valid market rows and 7 symbols absent from the price provider. Do not
fabricate prices for those rows or mark them inactive solely because this provider
omitted them. Reconcile the missing list against Borsa İstanbul's listed/delisted
company reference data.

This is a practical public-page adapter, not an official Borsa İstanbul data
license or a guaranteed API. It is assigned source priority 2. Keep priority 1
for official BIST/vendor files, which can replace these rows later. Historical
backfill still uses `vendor-csv` or normalized CSV.

### Provider files and historical backfill

The daily adapter does not provide arbitrary historical backfill. `fetch` downloads
one approved URL; `vendor-csv` maps a supplied CSV/JSON file using a reviewed
profile. They do not discover provider endpoints or authenticate licensed feeds.

Start with ONE real daily provider file, not a new crawler framework. The exact
normalized headers are:

```text
MarketData:
TradeDate,CompanyId,OpenPrice,HighPrice,LowPrice,ClosePrice,Volume,ValueTraded,SourcePriority

MarketIndexData:
TradeDate,IndexId,ClosePrice
```

Use actual exported IDs, ISO dates and decimal-point numbers. Volume is shares;
ValueTraded is actual currency turnover (not close × volume). Set the source's
currency/price basis/source priority accurately. For example, after reviewing the
source metadata in `examples/warehouse/bist-source.json`:

```bash
bash scripts/crawler-ubuntu.sh warehouse csv --table MarketData \
  --input /app/imports/prices-normalized.csv \
  --source /app/config/prices-source.json \
  --output /app/data/warehouse/prices.json

bash scripts/crawler-ubuntu.sh warehouse load \
  --input /app/data/warehouse/prices.json \
  --apply
```

Create `config/prices-source.json` from the example after reviewing it. Use
`--table MarketIndexData` and the three index columns for an index file. To avoid
manual conversion each day, make one verified `vendor-csv` profile for your actual
provider headers; the existing importer handles delimiter, dates, decimals,
identity lookups and unit scales.

For company enrichment, fill only verified blanks in the exported metadata CSV.
Copy `examples/warehouse/company-metadata-source.json` to
`config/company-metadata-source.json` and record your actual evidence. Then:

```bash
bash scripts/crawler-ubuntu.sh warehouse csv --table Company \
  --input /app/config/warehouse/company_metadata.csv \
  --source /app/config/company-metadata-source.json \
  --output /app/data/warehouse/companies-enriched.json

bash scripts/crawler-ubuntu.sh warehouse load \
  --input /app/data/warehouse/companies-enriched.json \
  --apply
```

Unknown IsActive is blank, not 0; verified active is 1, verified inactive is 0.
Master rows created by the seed can be enriched if their existing known values
agree. Conflicting pre-existing facts are skipped for review.

## 6. Open all tables in SQL Server or Grafana

SSMS: connect to your existing server, select `StockFundamentals` (or the database
you configured), expand Tables and refresh. You should see `dbo.Market`,
`dbo.Company`, `dbo.CompanyFundamental`, `dbo.MarketData`, `dbo.MarketIndexMaster`,
`dbo.MarketIndexData`, `dbo.MacroSovereign` and the two `stg` audit tables.

On the SQL host, the published address is `127.0.0.1,1433`. From another machine,
that loopback address refers to THAT machine: use an existing secure connection
or an SSH tunnel. Do not expose the SQL port publicly just to inspect these tables.

Grafana: Explore -> **StockFundamentals** -> Code -> **Format: Table**. Run one
SELECT at a time. Do not paste the entire multi-query SQL file into one panel:

```sql
SELECT DB_NAME() AS CurrentDatabase;
```

```sql
SELECT TOP (100) c.Ticker, f.*
FROM dbo.CompanyFundamental f
JOIN dbo.Company c ON c.CompanyId = f.CompanyId
ORDER BY f.FiscalYear DESC, f.FiscalQuarter DESC, c.Ticker;
```

`sql/warehouse-inspect.sql` has a query for every table, counts, and staging errors.
Setup grants the existing `fundamentals_reader_role` SELECT on the new tables;
your existing `grafana_reader` belongs to that role. If using a different login or
database, its owner must provide the appropriate user mapping/permissions.

## Working folder convention

Keep the source code where it is; no package reorganization is necessary.

| Folder | Use |
|---|---|
| `config/warehouse/` | Exported ID maps and editable company metadata |
| `config/` | Connection files and reviewed provider profiles |
| `imports/` | Source downloads you put there (read-only in Docker) |
| `data/warehouse/` | Generated bundles, fetched files, load results |
| `data/warehouse/raw/` | Content-hashed source archive |
| `sql/` | Setup and inspection scripts |

Run each acquisition/import command when needed, then `load`. Do not add cron or
another service until the pilot file and SQL results are correct. FactorStore is
outside this workflow.
