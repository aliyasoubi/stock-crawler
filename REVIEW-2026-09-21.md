Inputs: commit `163b4ec`, the 28 run summaries and 81 archived workbooks from the Ubuntu

## 1. Repository: the commit was a copy of the deployment, not a change

`163b4ec` added 7,259 files under `config/`: a full second copy of the project as it stood
on the Ubuntu host (`config/src`, `config/tests`, `config/scripts`, …) plus its runtime
data (`config/data/raw` with 7,140 files, run summaries, state, `check.json`). The root
`src/` stayed at 0.2.0 while `config/src/` was the real 0.2.1. The root `.gitignore`
patterns (`data/raw/`) are anchored to the repository root, so the nested copy was not
ignored. No credentials were in the commit (`config/local.env` held only paths/years).

Fixed by promoting the `config/` snapshot to the root (every root code file had a newer
counterpart, so nothing was lost), restoring `config/` as the configuration directory
(`companies.txt`, `companies_candidates.txt`, `kap_companies.json`, `REGISTRY-NOTES.md`),
untracking the runtime data, and rewriting `.gitignore` with depth-independent patterns
(`**/data/raw/`, `/data/`, `**/backups/`, `*.env`). The Ubuntu data is parked, untracked,
at `data/ubuntu-2026-09-19/` (raw workbooks, runs, state, `check.json`, the SQL backup
that was under `config/backups/`, and the leftover files) for offline replay. Dropped as
superseded: `config/env.example` (older than `.env.example`), `local.env*` (Mac-local,
referenced the removed opt-in setting), `companies_manual.txt` (candidates without the
header), `companies_pending.txt` (runtime artifact). Executable bits on `scripts/*.sh`
were restored.

## 3. Freshness re-fetched the same empty answers every run

`105757Z` re-fetched 251 companies one hour after `095346Z` had checked them, because a
company was only "fresh" when every requested year had a `published`/`already_parsed`
result. Any `no_filing` (issuer listed after 2022, no annual report yet), `unsupported`
(bank/insurance/finance format) or `failed` year made the company due again on every run,
and a `no_filing` year also set the company-level `last_error`, which defeated freshness
on its own. 41 tickers have no filing in any of 2022–2025, 162 more lack at least one
year, 52 are financial-sector: about a third of the list, re-asked hourly, same answer.

Changed: for the export source, **a requested year is "checked" whatever the answer**
(`published`, `already_parsed`, `no_filing`, `unsupported`, `failed`, `withdrawn`; not
`error`). Coverage is per year with its own timestamp, so the discovery interval (24 h)
re-checks it, `--refresh` overrides it, and changing `KAP_YEARS` still makes companies due
immediately. `no_filing` no longer sets `last_error` for that source, and the company's
coverage is written once per company instead of once per year (the state file is
rewritten whole on each save: 754 × 4 rewrites of a 570 KB file per run).

Also changed: the coverage key no longer contains the parser version. A parser upgrade is
applied by `reprocess` (zero HTTP); it does not re-download 754 companies whose bytes are
already on disk. The regression tests that encoded the old contract were rewritten to
assert the new one, with the reasons in their docstrings.

## 4. Coverage lost to titles: 42 distinct titles, 86 rows per full run

The export prints each row under the title the issuer had **when that report was
published**; the request is by MKK member ID. Rows whose title the registry did not know
were rejected (correctly: never attribute by batch order) and the years read as
`no_filing`. Three groups:

1. **KAP's own spelling variants (10 titles)** — same company, orthography differs:
   `BANVİT … SANAYİİ` vs `SANAYİ`, `PINAR SÜT MAMULLERİ` vs `MAMÜLLERİ`, `BRİSA
   BRIDGESTONE` vs `BRİDGESTONE`, `FEDERAL-MOGUL` vs `FEDERAL MOGUL`, a dropped `VE`,
   `YÜNSA … TİCARET ` with no legal form. Fixed with a normalized key (`loose_key`) tried
   only after the exact key fails and only within the batch's requested tickers. It folds
   diacritics/punctuation, drops `ve` and a trailing legal form, collapses a doubled final
   `i`, and never drops a name word; the loader refuses a seed where two tickers would
   share a key (none do, checked against all 754). Matches are listed in the summary as
   `normalized_title_matches` (21 rows in the archived workbooks).
2. **Real renames (32 titles)** — `BATISÖKE` → BSOKE, `DİTAŞ DOĞAN` → DITAS, `GARANTİ
   FİLO` → GARFL, `KOÇ FIAT KREDİ` → KSFIN, `MATRİKS BİLGİ DAĞITIM` → MTRKS, and the
   2025 renames with **new tickers**: `KOZA ALTIN` → TRALT, `KOZA ANADOLU` → TRMET, `İPEK
   DOĞAL ENERJİ` → TRENJ, `DAGİ YATIRIM HOLDİNG` → TRHOL, `TURCAS PETROL` → TRCAS. Their
   2024 rows were lost while 2025 published. New command **`verify-aliases`** proves these
   from the source: it requests the export for one member ID at a time, so every returned
   row belongs to that ID whatever title it carries. Proven titles go to
   `config/kap_aliases.json` with request, workbook hash and notification IDs as evidence;
   the company is made due again; a title the seed assigns to another ticker is reported
   as a conflict and never written. Candidates are derived from the newest summary
   (tickers that shared the batch and lack exactly those years), best-constrained first,
   capped by `--max-requests`. For `110856Z` that is 130 candidates at one request each,
   converging as titles resolve; `--tickers` targets a hand-picked set.
3. **Seed bug (1 title)** — `SHTRP` was stored as `SHELL & TURCAS` (double-escaped);
   corrected to `SHELL & TURCAS PETROL A.Ş.`.

## 5. Parser: HOLDING format and finance-sector revenue

- **`Sectoral Statement Type = holding`** was rejected as unsupported. That is KOÇ
  HOLDİNG, SABANCI, ŞİŞECAM, TURKCELL, AG ANADOLU, TEKFEN, DOĞAN and POLİSAN — the largest
  caps on the list. The ten exported items carry the same meaning as in the GENERAL
  format; the HOLDING format only splits turnover into `Revenue` (non-finance) and
  `Revenue from Finance Sector Operations`. Both are now kept as reported, in their own
  columns, with a warning stating that revenue excludes the finance line. Bank, insurance
  and finance formats remain unsupported.
- **`ÜNLÜ YATIRIM HOLDİNG`** (GENERAL format) reports its turnover only under the finance
  line and failed `missing required values: revenue` in every run. A row is now valid when
  either line is present; `revenue` stays null and the finance line is kept, with a
  warning. Rows with neither (ARENA 2022–24, MARMR 2025, Q YATIRIM 2022, KZBGY 2023 …)
  still fail: the source has no revenue line, and no zero is invented.
- Parser bumped to **1.2.0**; `reprocess` on the archived snapshots publishes all eight
  holding-format issuers and UNLU (verified offline; KCHOL 2025 revenue 1.838618 trillion
  TL from a `1000000TL` workbook, finance-sector revenue 918.677 billion kept apart,
  accounting identities pass).

## 6. Client export: 1,316 → 2,093 records, 391 → 611 companies

`export-company-fundamentals` was correct about the nine columns the ten-item workbook
cannot supply (OperatingIncome, EBITDA, debt, cash, FCF, EPS, shares; CompanyId needs the
client map). "0 pass" is expected until those inputs exist. Three things were wrong with
what it *could* supply:

- **Consolidated-only scope dropped 250 issuers entirely.** An issuer without subsidiaries
  files only unconsolidated statements; 749 of the 2,093 valid company-years exist only in
  that scope (AKSA, AKÇANSA, ASTOR, ADEL, AFYON, …). The default policy is now
  `consolidated-else-unconsolidated`: consolidated when it exists, otherwise the solo
  statement, and each record says which in `source.scope_basis`. `--scope consolidated`
  keeps the old strict behaviour.
- "791 source errors" counted the same problem row once per overlapping workbook. Errors
  are now de-duplicated per notification and categorized: 241 unsupported statement
  types, 76 unmatched titles, 18 rows without revenue/net profit.
- Revenue basis is explicit: `field_status.Revenue` is `reported`,
  `reported_excluding_finance_sector_revenue` (HOLDING) or
  `finance_sector_revenue_reported_as_revenue` (finance-only issuers), with the finance
  line in `source.unrounded_mapped_amounts.FinanceSectorRevenue`.

Replay of the 81 workbooks: 2,093 records, 611 companies, 0 accounting-identity issues,
0 HTTP.

## 7. Not changed, worth knowing

- `config/companies_candidates.txt` is the KAP member list, not the equity list: it
  contains `KAP TEST A.Ş.`, `BNP PARIBAS ISSUANCE B.V.`, `GOLDMAN SACHS INTERNATIONAL`,
  the Mint (`DRPHN`), TOKİ, ~25 asset-leasing SPVs (`VARLIK KİRALAMA`) and the financial
  sector. Each costs a batch slot and answers `no_filing`/`unsupported`. With per-year
  freshness that cost is paid once per interval instead of every run; curating the list
  would remove it.
- `last_error` on `dbo.companies` is a company-level column fed by per-year results; for
  the export source it now only reflects parse failures and is not used for freshness.
  The per-year detail is in the run summary and in `data/state/revalidation.json`
  (`coverage:*` entries now also carry `status_by_year`). The old `coverage:*/1.1.1`
  entries are inert.
- The next data phase (OperatingIncome, EBITDA, cash, debt, EPS, shares) needs additional
  export item IDs or full reports; nothing here invents them.

## 8. Apply on the Ubuntu host

```bash
cd ~/projects/stock-crawler
git pull                      # new layout: code at the root, config/ is configuration only
bash scripts/crawler-ubuntu.sh build
docker run --rm --pull=never stock-crawler:local --version   # expect: stock-crawler 0.2.2
```

Edit `.env`: `MAX_REQUESTS_PER_RUN=40`. Then, in this order:

```bash
bash scripts/backup.sh
bash scripts/crawler-ubuntu.sh db
# 1. re-parse stored workbooks with parser 1.2.0: holding-format issuers and UNLU publish. Zero HTTP.
bash scripts/crawler-ubuntu.sh docker reprocess --company-file /app/config/companies_candidates.txt
python3 scripts/review-run.py
# 2. prove historical titles (one request per candidate; repeat until "nothing to verify")
bash scripts/crawler-ubuntu.sh docker verify-aliases --max-requests 20
# 3. normal sync; the first pass after the upgrade re-checks everything once (31 requests)
bash scripts/crawler-ubuntu.sh docker sync --company-file /app/config/companies_candidates.txt
python3 scripts/review-run.py
# 4. client review with the new scope policy
bash scripts/crawler-ubuntu.sh docker export-company-fundamentals --currency TRY \
  --output /app/data/CompanyFundamental_Review.json
```

Commit `config/kap_aliases.json` after step 2 so the proven titles travel with the
registry. `verify-aliases` writes nothing to SQL; `reprocess` and `sync` do.
