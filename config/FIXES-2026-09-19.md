Docker explicitly requires a rebuild when source in the build directory changes:
[Docker Compose build documentation](https://docs.docker.com/reference/cli/docker/compose/build/).

## Changes in this release

| Area | Result |
|---|---|
| Logger crash | Existing logging initialization retained and exercised by unmatched-row regression tests. |
| Historical company names | Added exact ARSAN and ARSNF aliases with primary-source evidence in `config/REGISTRY-NOTES.md`; no fuzzy matching. |
| Client export | Restored `CompanyId` as the first field, populated only by the supplied client ID map; missing IDs remain null and block completeness. |
| Rejections | JSON and console show rejection/exclusion counts. Rejected rows make the command return 1 even when other rows publish. |
| Conflicting rows | All conflicting occurrences of a notification in a live batch are rejected; the first value is not arbitrarily published. Other companies continue. |
| Missing years | Each requested year gets an explicit result, including `no_filing`; absent years do not count as collected. |
| Freshness | Stored per company source ID, parser version, and fiscal year with individual collection timestamps. New windows, stale years, and parser changes become due. |
| Reused clients | Each sync plan resets in-memory batches, failures and rejections. `--refresh` actually fetches again. |
| Unexpected failures | A current run summary is saved before an unexpected exception is re-raised. This does not cover forced termination, disk failure, or failure before sync starts. |
| Company cap | Effective cap/selected count are recorded; a larger CLI limit produces a clear warning. |
| Measuring unit | Existing schema-2 column, SQL views and parser plumbing retained. Parser bumped so offline reprocessing can populate old comparative rows. Comparison suppresses monetary deltas across differing measuring-unit dates. |
| Deployment | Added `crawler-ubuntu.sh build`, a version bump, and `scripts/review-run.py`. |
| Packaging | Excludes credentials, Git history, runtime data, environments and caches. Added Docker build-context exclusions and Git ignore entries. |

Both SQL schema copies are identical. Migration is additive and idempotent; existing
current rows with a null measuring-unit date are backfilled. Existing comparative
rows require `reprocess`. A measuring-unit date is report-basis metadata, not proof
that every historical report applies IAS 29 and not a substitute for CPI adjustment.

## Apply the update in your existing checkout

The ZIP contains a `stock-crawler/` directory. Copy its files over the **existing**
`~/projects/stock-crawler` directory. The ZIP has no `.env`, runtime `data/`, or
`.git/`, so extracting it preserves those files. Do not delete your existing checkout
or database volume. Retain your existing Compose project name.

For a download named `stock-crawler-fixed.zip`:

```bash
unzip -o ~/Downloads/stock-crawler-fixed.zip -d ~/projects
cd ~/projects/stock-crawler
```

Adjust the download path/name if your browser uses another one.

Run each following command separately and stop if a build/migration fails:

```bash
bash scripts/crawler-ubuntu.sh build
```

This rebuilds only the crawler service using the existing Compose build settings.
Build-time package access uses the build proxy settings in `docker-compose.yml`
(currently the host HTTP proxy on port 8118); the runtime SOCKS proxy on 10808 is a
separate configuration. Keep the previously working build proxy available. A failed
build leaves the old image in place, so verify the version before continuing.

```bash
docker run --rm --pull=never stock-crawler:local --version
```

Expected: **`stock-crawler 0.2.1`**. This command does not contact KAP or SQL Server.

```bash
bash scripts/crawler-ubuntu.sh db
bash scripts/backup.sh
bash scripts/crawler-ubuntu.sh docker init-db
```

The database command reuses the current named SQL volume. The backup script writes a
native database backup plus raw/state files. `init-db` applies the schema-2 column,
backfill and view definitions. Never run `docker compose down -v` for this update.

## Pilot, review, and full run

Edit these four settings in your existing `.env`, preserving passwords and proxy
configuration. Keeping `KAP_YEARS=[2024,2025]` matches your uploaded configuration.

```dotenv
MAX_COMPANIES_PER_RUN=1000
MAX_REQUESTS_PER_RUN=50
REQUEST_DELAY_MIN_SECONDS=15
REQUEST_DELAY_MAX_SECONDS=30
```

These are run ceilings and pacing settings, not a guarantee of source availability.
Use a real contact in your existing `HTTP_USER_AGENT`. No image rebuild is needed
when changing `.env`; each one-shot container reads it again.

First check the issuer that crashed (one batch):

```bash
bash scripts/crawler-ubuntu.sh docker sync --tickers ARSAN --refresh
python3 scripts/review-run.py
```

Then run up to 100 due companies:

```bash
bash scripts/crawler-ubuntu.sh docker sync \
  --company-file /app/config/companies_candidates.txt --limit 100
python3 scripts/review-run.py
```

Read the printed timestamps, stopped reason, rejects and statuses. Exit **0** means
no reported source/parse issues; **1** means some results need review; **2** means a
budget, cooldown or access-stop condition. Valid rows can already be stored during a
partial run. Unsupported sectors and missing source values will not be forced into
valid rows merely to obtain exit 0.

Once the pilot is understood, run the complete candidate list manually:

```bash
bash scripts/crawler-ubuntu.sh docker sync \
  --company-file /app/config/companies_candidates.txt
python3 scripts/review-run.py
```

Repeat that same command on later days. Do not routinely add `--refresh`; normal
freshness skips recently completed years. Deferred companies can be processed in a
later run. With at most 25 companies per request, the 754-company seed needs at most
31 successful requests if every company is due and eligible; retries consume more
of the 50-attempt ceiling. A stopped run is explicitly reported rather than silently
assumed complete. Respect any recorded access cooldown/block.

For historical windows, change only `KAP_YEARS` to up to five completed years (for
example `[2016,2017,2018,2019,2020]`), then run the same command in a later collection
window. Changing years no longer requires `--refresh`. Legacy coverage entries lack
per-year timestamps, so the first run after upgrading may revisit previously fresh
companies. Existing identical report versions remain deduplicated within a parser
version; parser 1.1.1 creates new audit versions when reparsing old 1.1.0 snapshots.

To reparse saved snapshots entirely offline after the migration:

```bash
bash scripts/crawler-ubuntu.sh docker reprocess \
  --company-file /app/config/companies_candidates.txt
```

`cache_miss` is expected for companies never captured. This makes no KAP requests
and does not manufacture missing years or unavailable fields.

Docker, SQL Server and Grafana runtime were not available for validation here.
The full candidate list was not fetched live. The test pass count does not imply
all 754 companies or all requested financial metrics are supported.

The current request still contains the ten reviewed comparison item IDs. Additional
metrics, bank/insurance/factoring mappings, live financial-report discovery and an
independent reconciliation source require reviewed real fixtures. Their absence is
explicit; this fix does not replace missing OperatingIncome/EBITDA/etc. with zeros.
A second unofficial source is a reconciliation input, not automatic ground truth.

The uploaded Git history tracks credential-bearing files (`.env`, `.env.save`,
`local.env`). They are omitted from this distributable. Ignore rules do not untrack
files already in your repository. If these credentials were exposed, rotate them;
`init-db` does not rotate existing logins. History cleanup should be coordinated
separately because it rewrites commit identities. To stop tracking the local copies
without deleting them, the review's cleanup command can be completed as:

```bash
git rm --cached --ignore-unmatch .env .env.save local.env .crawler-manual.lock \
  data/test_export.json data/CompanyFundamental_Review.json
```
